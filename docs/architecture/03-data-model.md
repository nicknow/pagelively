# 03 — Data model

Three stores, three shapes: **D1** for metadata (pages/files), **R2** for bytes
(`pages/{id}/{rev}/…`), **KV** for the optional Access JWKS cache. The D1 schema is the spec §8
schema verbatim, already applied by `migrations/0001_init.sql` to local D1 and to every test
file's isolated database.

## D1 — schema and semantics

```sql
CREATE TABLE pages (
  id            TEXT PRIMARY KEY,      -- nanoid (Web Crypto, ids.ts)
  slug          TEXT UNIQUE,           -- nullable, lowercase, reserved-checked (ADR 0007)
  title         TEXT,
  kind          TEXT NOT NULL,         -- image|html|markdown|bundle (§4)
  rev           INTEGER NOT NULL DEFAULT 1,  -- publish revision (ADR 0006)
  entry_path    TEXT NOT NULL,         -- "index.html" for document kinds; file name for image/raw
  raw_md_path   TEXT,                  -- "source.md" for markdown entries (nullable)
  show_source   INTEGER DEFAULT 0,     -- expose raw markdown (0/1)
  visibility    TEXT DEFAULT 'public', -- public|unlisted (§8, forward-looking)
  created_at    TEXT NOT NULL,         -- ISO-8601 UTC, set by the Worker
  updated_at    TEXT NOT NULL
);

CREATE TABLE files (
  page_id       TEXT NOT NULL,
  path          TEXT NOT NULL,         -- relative path within the bundle (§6)
  r2_key        TEXT NOT NULL,         -- pages/{id}/{rev}/{path} (§8)
  content_type  TEXT NOT NULL,
  size          INTEGER NOT NULL,
  PRIMARY KEY (page_id, path),
  FOREIGN KEY (page_id) REFERENCES pages(id) ON DELETE CASCADE
);

CREATE INDEX idx_pages_slug ON pages(slug);
```

### Semantics and invariants

- **`id`** — 8–10 URL-safe chars (`[A-Za-z0-9_-]`), generated by `crypto.getRandomValues`
  (ADR 0002; spec §4 "nanoid or Web Crypto"). Immutable, never reused.
- **`slug`** — nullable; `UNIQUE` is the backstop, the app does collision handling first:
  auto-generated slugs get deterministic `-2`/`-3` suffixes (ADR 0007), user-supplied slugs
  colliding return 409 (ADR 0007, S17 AC). Lowercase-only by construction.
- **`rev`** — starts at 1; bumped **only** by content-affecting actions (ADR 0006/OQ-04):
  file add/replace/delete, entry change, markdown (re-)render. Metadata edits
  (slug/title/visibility/show_source) do **not** bump — cache purge covers them. `rev` is the
  cache-busting dimension: entry HTML and the `<base>` href embed it, asset URLs are
  rev-stable (04).
- **`entry_path`** — **entry normalization rule**: document kinds (`html`, `markdown`,
  `bundle`-with-document-entry) store the served entry as `index.html` at the rev-folder root
  (spec §8 layout); image/raw single-file pages store the file under its own name
  (`photo.jpg`) and `entry_path` records it (the 301 target, §6). For markdown entries
  (kind `markdown`, or `bundle` with a `.md` entry — OQ-05: rendered through the same
  pipeline), `raw_md_path = "source.md"` and `show_source` controls whether the template links
  it.
- **`files.r2_key` embeds `rev`** (spec §8). On a rev bump (S18), the implementer writes the
  new rev folder, then **rewrites all `files` rows** to the new `r2_key`s (planner
  meta-observation; the old folder is left for OQ-10 GC — human decision pending).
- **Timestamps** are ISO-8601 UTC strings set by the Worker at write time (no SQL defaults —
  the Worker is the only writer).
- **No new tables in v1.** `visibility = unlisted` is stored but unused until a listing exists
  (§8; OQ-09). No rev-GC bookkeeping (OQ-10).

### Query discipline (S10 AC, risk R4)

- `getBySlug` → `idx_pages_slug`; `getById` → PK. Both index-covered.
- `list` → admin-only scan ordered `created_at DESC`; the table is small at personal scale.
  **No index on `created_at`**: D1 indexes add a written row per write (verified pricing note)
  — an index for an admin-only, low-cardinality sort is pure cost.
- Every read path used by public serving is a single-row lookup: two index-covered reads max
  per entry request (one for `/p/{id}`, one for `/{slug}`).

### Migration policy

- Append-only: `0001_init.sql` is immutable; later migrations (`0002_…`, numbered) add/alter.
  Tests apply all migrations in order via `readD1Migrations` + `applyD1Migrations` (06).
- Schema drift is caught by tests asserting against the real migrated schema, never a fixture
  copy.

## R2 — key layout and metadata

```
pages/{id}/{rev}/index.html        # entry (html or rendered markdown) (§8)
pages/{id}/{rev}/source.md         # original markdown (markdown entries only)
pages/{id}/{rev}/images/pic.png    # assets, original relative paths preserved (§6)
pages/{id}/{rev}/style.css
pages/{id}/{rev}/photo.jpg         # image/raw pages: the file itself (entry_path)
```

- Keys are built **only** through `rev.ts:buildR2Key` (02). `../` and absolute paths are
  rejected at upload (S17 AC).
- **httpMetadata at upload** (verified: R2 stores and echoes it): `content_type` +
  `Cache-Control: public, max-age=31536000, immutable` for assets. This is what makes CDN-host
  serving correct with no Worker in the path (§3, §11; ADR 0006).
- Deleting a page removes rows (cascade) and **all** `pages/{id}/…` objects (paginated
  list+delete — R2 list API; S11 AC). Deleting/ replacing one file removes only that object.
- Republish writes a fresh `{rev}` folder and flips the pointer in D1 — old folders are simply
  left in place (no GC v1, OQ-10).

## KV — optional JWKS cache (S14)

- Key: `access-jwks`. Value: the JSON of the fetched JWKS (`{ keys: [...] }`).
- TTL: `expirationTtl: 3600` (1 h). Rationale (verified quotas): 1 h ⇒ ≤ 24 writes/day, far
  under the 1,000 writes/day free limit; a 1 h staleness bound on key rotation is acceptable
  and bounded (risk R9).
- Behavior: miss/stale/corrupt → refetch from `https://{ACCESS_TEAM_DOMAIN}/cdn-cgi/access/certs`;
  write failures ignored; **KV absent → fetch every time** (the app works without the binding,
  §2, §9); fetch failure → the gate fails closed (ADR 0005, S14 AC).
- Version suffix note: if `ACCESS_TEAM_DOMAIN` changes, setup re-deploys with a new config;
  the 1 h TTL bounds cross-config staleness without extra key bookkeeping (documented
  trade-off, not a bug).
