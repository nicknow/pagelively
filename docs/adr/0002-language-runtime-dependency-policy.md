# 0002: Language, runtime, and dependency policy

- Status: accepted
- Date: 2026-07-31

## Context

The spec (§7, §14) mandates TypeScript on Workers, a compact Markdown renderer, nanoid _or_
Web Crypto ids, and Web-Crypto JWT verification with "no native crypto deps". The roadmap
(§8) asks Phase 2 to lock the language/tooling, the `marked` pin + Workers compatibility, the
id mechanism, and the router question. Bundle size is a hard constraint: 3 MB compressed on
the free plan (verified: <https://developers.cloudflare.com/workers/platform/limits/>), and
the admin must stay buildless (§10).

Options considered: (a) a router library (Hono, itty-router) for the ~10 literal path rules;
(b) `nanoid` as a dependency; (c) `marked` with a sanitizer (DOMPurify); (d) hand-rolled JWT
verification with Web Crypto instead of `jose`.

## Decision

1. **Language/runtime**: TypeScript `strict`, target `ES2022`, ES-module module-worker format
   (required by the test tooling — verified:
   <https://developers.cloudflare.com/workers/testing/vitest-integration/migration-guides/migrate-from-unstable-dev/>).
   No `nodejs_compat`. `Env` generated by `wrangler types` (ADR 0001).
2. **No router library.** The routing surface is a handful of literal prefixes (§5) — a pure,
   exhaustively table-tested `classifyPath` function is smaller, faster, and more testable
   than a dependency. This keeps the free-plan bundle budget for what matters.
3. **Ids via Web Crypto, not `nanoid`** (spec §4 explicitly allows): `crypto.getRandomValues`
   → 8–10 URL-safe chars. Zero bytes, zero supply-chain surface; uniqueness is by entropy
   (verified practice; the 10k-sample uniqueness check is an S01 AC).
4. **Runtime deps are exactly two:** `marked` (^18) and `jose` (latest on install).
   - `marked`: the spec's chosen renderer (§7, §14); `marked.parse(md[, opts])` is synchronous
     and isomorphic — runs in workerd/Workers without shims (verified against the official
     repo docs). It has **no built-in sanitizer since v5**; raw HTML passes through verbatim by
     design. `ALLOW_RAW_HTML_IN_MD=false` is therefore implemented as a custom renderer
     (escape `html`/`tag` tokens) — the sanctioned v5+ mechanism — not a sanitizer dependency.
     Source: <https://github.com/markedjs/marked/blob/master/docs/USING_ADVANCED.md>,
     <https://github.com/markedjs/marked/blob/master/src/Renderer.ts>
   - `jose`: the Cloudflare-documented library for Access JWT verification
     (`createRemoteJWKSet` + `jwtVerify`). Hand-rolling JWKS/kid/alg handling is exactly where
     verification bugs (risk R9) live; jose is small, audited, and official-recommended.
     Source: <https://developers.cloudflare.com/changelog/product/workers/5/>
   - Everything else stays dev-only. Deferred: `fflate` (zip, §16), DOMPurify (no untrusted
     input in v1 — trust model, risk R12).
5. **TypeScript 6.0.3, Wrangler 4.116.0, ESLint 10 flat + typescript-eslint, Prettier 3.9.6**
   — pinned in `package.json` (caret), drift tracked as risk R13.

## Consequences

- The deployed Worker has a tiny dependency surface: `marked` + `jose`; bundle stays far under
  the 3 MB compressed free limit (`npm run build` is the gate from S05).
- Router/slug/id/header logic is pure TypeScript — the front-loaded unit-test strategy (S01–S09)
  has zero binding friction.
- Markdown raw-HTML behavior is explicit and testable in both `ALLOW_RAW_HTML_IN_MD` modes
  (S05 AC), matching the single-operator trust model (§7).
- Supersedes nothing; consistent with ADR 0001's Phase-0 toolchain seeding.

## Consequences recap (trade-offs)

- Hand-rolled router: no ecosystem features (middleware, etc.) — not needed at this surface;
  the entrypoint constraint (ADR 0006) keeps it one file.
- Web Crypto ids: no dependency, but ids are only as unique as `getRandomValues` — fine for
  8–10 chars at personal scale; the S01 uniqueness test guards the implementation.
