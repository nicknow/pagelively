# 0001: Phase 0 foundations — repo layout, toolchain, devcontainer

- Status: accepted
- Date: 2026-07-30

## Context

Phase 0 establishes the repository skeleton everything else builds on: the knowledge-management
layout (`docs/` / `.ai/` / `.work/`), a toolchain on which `install → build → typecheck →
lint → test` all run locally with zero cloud setup, and a devcontainer that reproduces it from
a fresh clone. Three source documents from `.initial-inputs/` must be persisted verbatim.

Key platform facts were verified against current official Cloudflare documentation rather than
assumed:

- **Wrangler Node support:** the CLI supports the Current, Active, and Maintenance Node.js
  releases. As of this writing that makes **Node 24 (Active LTS)** the right pin — Current LTS,
  matching Wrangler's supported range.
  Source: <https://developers.cloudflare.com/workers/wrangler/install-and-update/>
- **Recommended local test tooling:** Cloudflare's recommended unit-test tooling is the
  **Workers Vitest integration** (`@cloudflare/vitest-pool-workers`): tests run inside `workerd`
  via Miniflare, with real R2/D1/KV binding emulation and per-test-file isolated storage.
  Source: <https://developers.cloudflare.com/workers/testing/vitest-integration/>
- **Local D1 migrations:** `wrangler d1 migrations apply <db> --local` applies migrations to a
  local SQLite in `.wrangler/state`; `wrangler dev` uses local mode by default (port 8787).
  Sources: <https://developers.cloudflare.com/d1/reference/migrations/>,
  <https://developers.cloudflare.com/d1/best-practices/local-development/>,
  <https://developers.cloudflare.com/workers/local-development/>

## Decision

1. **Repo layout.** Adopt the knowledge-management model exactly: `docs/` (permanent project
   knowledge), `.ai/` (permanent agent knowledge: `prompts/`, `standards/`, `workflows/`, plus
   git-ignored `scratch/`, `cache/`, `logs/`), and `.work/` (disposable per-role scratch,
   git-ignored except for a tracked README per role). `AGENTS.md` is a small entry point that
   routes to these docs.

2. **Source documents.** Persist verbatim from `.initial-inputs/`:
   - `pages-app-spec.md` → `docs/product-spec.md` (the authoritative spec).
   - `documentation-article.md` → `.ai/knowledge-management.md`.
   - `pages-build-agent-brief.md` → `.ai/team-brief.md`.
     Note: the brief's Part A names the destination `.ai/pages-build-agent-brief.md`, but the
     Phase-0 checklist and the orchestrator prompt both name `.ai/team-brief.md`; the checklist
     name wins (single copy, no duplication).

3. **Toolchain (seeded in Phase 0, formalized by the architecture ADRs).**
   - Runtime: Cloudflare Workers, TypeScript (ES modules, module-worker format), Wrangler 4+
     as a dev dependency.
   - Tests: Vitest + `@cloudflare/vitest-pool-workers` (`cloudflareTest()` plugin reading
     `wrangler.toml`); D1 migrations applied per test file via `readD1Migrations` /
     `applyD1Migrations` in a setup file using top-level `await` (Vitest setup files are module
     side effects — an exported function would never be invoked).
   - Coverage: `@vitest/coverage-istanbul`. The Workers pool rejects the v8 provider — V8 native
     coverage requires `node:inspector`, which is not functional in the Workers runtime
     (verified in the installed pool source). Threshold placeholder 80%; final threshold set by
     the architecture phase.
   - Lint/format: ESLint 9 flat config (`typescript-eslint` recommended) + Prettier.
   - Types: `worker-configuration.d.ts` is generated by `npm run types` (`wrangler types`) and
     committed, so a fresh clone needs no generation step. Wrangler 4 inlines the runtime types
     (derived from the `compatibility_date` / flags in `wrangler.toml`), which replaces
     `@cloudflare/workers-types` — that package is no longer referenced anywhere. Regeneration is
     byte-identical (verified); rerun after any `wrangler.toml` change.
     Sources: <https://developers.cloudflare.com/workers/languages/typescript/>,
     <https://developers.cloudflare.com/workers/wrangler/commands/general/#types>

4. **Devcontainer.** Pin `mcr.microsoft.com/devcontainers/typescript-node:5.0.3-24-bookworm`
   (exact tag verified against the MCR tag registry: Node 24, Debian bookworm). `postCreateCommand`
   runs `npm install && npm run db:local:migrate`; port 8787 forwarded for `wrangler dev`.
   No Cloudflare credentials anywhere in the image or config.

5. **Placeholder policy.** `wrangler.toml` bindings/vars and `.env.example` / `.dev.vars.example`
   contain placeholders only. Real resource IDs and domains are written by the human-run
   `setup.mjs` at provision time (later slice). This is what makes "zero cloud setup" and
   "never commit secrets" hold simultaneously.

6. **Migration seed.** `migrations/0001_init.sql` is the spec §8 schema verbatim (pages, files,
   slug index), so local D1 and test setup have a real schema from day one.

## Consequences

- A fresh clone + devcontainer can install, build, typecheck, lint, test, and run the local dev
  loop with no accounts and no network-dependent Cloudflare state.
- The team has a stable base for Phase 1 (planning) and Phase 2 (architecture); the architecture
  phase will re-verify and lock the toolchain choices with its own ADRs.
- Placeholder bindings mean `wrangler dev` / tests can never accidentally touch real resources.
- `worker-configuration.d.ts` can drift from `wrangler.toml` if a config change forgets
  `npm run types`; the typecheck gate (which reads the generated file) keeps drift visible.
